2) High-level call graph
========================
A) Main non-LTE run + observer spectra
1. model_Bstar1060/batch.sh
2. batch.sh sources aliases_for_cmfgen.sh (env+aliases)
3. batch.sh creates generic H/He links + sources batch_ins.sh (bulk atomic links)
4. batch.sh runs cmfgen_dev.exe and writes batch.log
5. batch.sh enters obs/ and runs tcsh ./batobs.sh
6. obs/batobs.sh calls ../batch.sh assign (link-only mode)
7. obs/batobs.sh sources obs/bat_ins.sh (3 cmf_flux runs -> obs_fin_* variants)
8. obs/batobs.sh runs one continuum cmf_flux pass -> obs_cont/hydro_cont/etc
9. obs/batobs.sh cleans transient files and calls ../clean.sh

B) LTE subfolder run
1. lte/ltebat.sh
2. ltebat.sh calls ../batch.sh ass (non-empty arg => link-only mode)
3. ltebat.sh runs main_lte.exe and writes ltebat.log

C) New model staging
1. models/ostar/cpmod.sh old_model new_model
2. Copies baseline files and old *OUT files to new dir
3. Calls out2in alias/script to rename *OUT -> *_IN
4. Optional SN-specific copies if SN files are present

6) Python reimplementation blueprint (recommended)
==================================================

6.1 Module split
----------------
1. env.py
- Resolve cmfdist/ATOMIC paths without tcsh aliases.
- Read defaults from current environment, then fallback to canonical paths.

2. links.py
- Apply atomic link manifests.
- Validate link targets and report broken/missing targets (especially *_F_TO_S).
- Support link-only mode equivalent to `batch.sh <arg>`.

3. runner_cmfgen.py
- Reproduce batch.sh non-link behavior:
  - create T_IN link
  - run cmfgen_dev.exe
  - structured logging to batch.log
  - optional run obs stage

4. runner_obs.py
- Reproduce batobs.sh + bat_ins.sh:
  - create additional observer links
  - generate CMF_FLUX_PARAM from template edits
  - run VTURB sweep list
  - apply deterministic rename policy
  - retain/delete transients per policy

5. runner_lte.py
- Reproduce ltebat.sh:
  - call link-only prep in parent context
  - run main_lte.exe
  - log to ltebat.log

6. staging.py
- Reimplement cpmod/out2in logic with explicit file inventory and safety checks.

7. cleanup.py
- Replace blind rm lists with explicit, configurable cleanup profile.


6.2 Data-driven config (instead of hardcoded shell)
---------------------------------------------------
Use YAML/TOML inputs:
- vturb_runs: [15, 10, 20]
- continuum_patch rules for CMF_FLUX_PARAM
- link manifests (optionally pre-generated from batch_ins.sh)

6.3 Suggested execution state machine
-------------------------------------
- stage_model -> prepare_links -> run_cmfgen -> run_obs_vturb -> run_obs_continuum -> cleanup
- optional: run_lte
- each stage writes JSON status + timestamps + command exit code


7) Migration pitfalls to handle explicitly
==========================================
1. tcsh-specific behavior
- Current scripts rely on `source`, aliases, tcsh conditionals.
- Python should not depend on shell alias expansion.

2. `batch.sh` self-path discovery via lsof
- Current line 12 uses `/usr/bin/lsof` parsing.
- Python should use `Path(__file__).resolve().parent`.

3. Unsafe wildcard usage
- `out2in.sh` uses `ls *OUT`; fails noisily when no match.
- Use glob APIs with empty-list-safe handling.

4. Destructive cleanup defaults
- Existing clean scripts remove aggressively and use repeated rm/find.
- Add dry-run mode and clear preservation policy.

5. Broken/missing F_TO_S link targets
- Must validate generated link targets before run.
- Fail fast or downgrade with warnings by policy.

6. Concurrency and logging
- Scripts background processes then `wait`; logs mix runtime and notes.
- Python should stream subprocess output and keep per-stage logs.

7. Implicit working-directory assumptions
- All scripts assume they run from exact model subdir.
- Python should normalize cwd per stage and use absolute paths internally.
